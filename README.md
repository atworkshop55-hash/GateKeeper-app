# Gate Keeper for RevPi

An Android tablet and Windows app for operating and monitoring Revolution Pi gate-control systems over secure MQTT. This public repository is for sharing test builds, release notes, and the project's direction; the application source remains in the private development repository.

> **Experimental test build:** use only with a compatible lab/test Node-RED and Mosquitto setup. Do not connect an unvalidated build to a live gate or rely on it for safety-critical operation. Verify the complete safe-state behavior on your own test hardware before any wider use.

## Current test build: V1.3.15 (1.3.15+18)

Download from the [V1.3.15 release](https://github.com/atworkshop55-hash/GateKeeper-app/releases/tag/V1.3.15):

- **Gate_Keeper_V1.3.15.apk**: Android update. Install over the existing app to preserve enrollment.
- **Gate_Keeper_V1.3.15_windows_x64.zip**: complete Windows x64 bundle. Extract the whole ZIP and keep its executable, DLLs and data directory together. Requires the Visual C++ x64 runtime and its own enrolled device identity.
- **SHA256SUMS.txt**: SHA-256 checksums for both downloads.

Highlights:

- Enroll a tablet by scanning a one-time QR code generated by the Node-RED Tablets page. The broker CA certificate is embedded in the QR; each tablet receives its own MQTT identity, which can be revoked.
- Show live RevPi hardware telemetry and system status.
- Provide gate controls, audit logs, diagnostics, and admin functions according to the signed-in user's role.
- Use the same configured inactivity timeout as the web UI, with server force-logout and tablet logout handling.
- Show offline, stale, local-control and remote-disabled gate states instead of incorrectly displaying Available.
- Persist accepted remote command presses and control-session events, with gate/operator/device context and the last observed position on session release.
- Separate remote operation, local pendant operation and idle/unexpected gate-position observations into **REMOTE_OPERATION**, **LOCAL_OPERATION** and **GATE_STATE** categories. Historical OPERATION records are preserved; full category names appear in text/PDF exports.
- Confirm limit-derived changes with at least two fresh replies spanning 500 ms. Restart establishes a quiet RAM baseline; changes found after a communications gap have unknown change time and are not described as forced movement.
- Gate control uses a server heartbeat; the server is responsible for releasing the gate to its configured safe state when the heartbeat is lost. Test and verify this behavior with non-live hardware.

Requires the matching V1.3.15 Node-RED configuration, a compatible TLS-enabled MQTT broker and administrator setup. Flow sources are maintained separately in a private repository; obtain the matching configuration from the administrator. The app does not include broker credentials.

### VPN testing

Connect your existing VPN first and verify routing to the enrolled broker. This release adds no VPN client or configuration. TLS certificate/hostname checks and control timeouts are unchanged: gate freshness is 4.5 seconds, session timeout is 3 seconds and hardware-display freshness is 6 seconds. Latency or interruption may correctly block control; no safety timeout has been relaxed. End-to-end VPN acceptance remains pending.

### Validation

64 app tests, 160 isolated backend tests and 24 helper tests passed. Android version metadata and Windows startup were verified; release asset hashes are checked against the development releases. Targeted audit/export analysis is clean, not a claim of clean repository-wide lint or physical commissioning.

- Validate a second device, revocation, ownership and reconnect behavior.
- Clarify observed MAC address source, age and last-seen behavior.
