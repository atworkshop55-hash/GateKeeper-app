# Gate Keeper for RevPi

An Android tablet app for operating and monitoring Revolution Pi gate-control systems over secure MQTT. This public repository is for sharing test builds, release notes, and the project's direction; the application source remains in the private development repository.

> **Experimental test build:** use only with a compatible lab/test Node-RED and Mosquitto setup. Do not connect an unvalidated build to a live gate or rely on it for safety-critical operation. Verify the complete safe-state behavior on your own test hardware before any wider use.

## Current test build: V1.2

Download **Gate_Keeper_V1.2.apk** from the [V1.2 release](https://github.com/atworkshop55-hash/GateKeeper-app/releases/tag/V1.2).

Highlights:

- Enroll a tablet by scanning a one-time QR code generated by the Node-RED Tablets page. The broker CA certificate is embedded in the QR; each tablet receives its own MQTT identity, which can be revoked.
- Show live RevPi hardware telemetry and system status.
- Provide gate controls, audit logs, diagnostics, and admin functions according to the signed-in user's role.
- Use the same configured inactivity timeout as the web UI. Server force-logout and tablet logout are implemented; the latest partial-logout fixes still need validation on the tablet.
- Gate control uses a server heartbeat; the server is responsible for releasing the gate to its configured safe state when the heartbeat is lost. Test and verify this behavior with non-live hardware.

The matching Node-RED flow work is on the [`feature/tablet-qr-enrollment` branch](https://github.com/atworkshop55-hash/revpi-node-red-flows/tree/feature/tablet-qr-enrollment) of the public [revpi-node-red-flows repository](https://github.com/atworkshop55-hash/revpi-node-red-flows). A compatible TLS-enabled MQTT broker, Node-RED configuration, and administrator setup are required; the APK does not include broker credentials.

## Project direction / planned work

- Log out when the tablet is locked or its screen turns off (including the physical power button), and ensure any active gate is left in its safe state.
- Add a clear network-connectivity check and bounded MQTT connection timeout so connection tests cannot spin indefinitely.
- Continue validating force logout, inactivity timeout, session transitions, and safe-state handling on test hardware.

## Feedback

For testing feedback, include the APK version, tablet model/Android version, whether the broker was reachable, the action taken, and any non-sensitive error message. Do not post passwords, QR enrollment payloads, private certificates, or live broker credentials in issues.
